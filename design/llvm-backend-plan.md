# The LLVM backend: plan after the proof of concept

This plan turns the strategy of [compiling Fa with LLVM](compilation-with-llvm.md) into the first concrete steps, with what the proof of concept in `packages/codegen-llvm` (crate `fa-codegen-llvm`) measured. It is not a language specification: `documentation/` stays the source of truth. Where this plan departs from the strategy, the [disagreements](#where-this-plan-departs-from-the-strategy) section says why.

## Toolchain

| Piece | Choice |
| --- | --- |
| LLVM | **18.1** (Ubuntu 24.04 packages), pinned. `llc`, `ld.lld`, `wasm-ld` and `libLLVM.so` come from the same install. |
| Install | `just setup-llvm` (`scripts/setup-llvm.sh`): `apt-get download` + `dpkg -x` into `~/.local/llvm18`, no root. `FA_LLVM_WITH_CLANG=1` adds clang 18. |
| Environment | `export LLVM_SYS_181_PREFIX="$HOME/.local/llvm18/usr/lib/llvm-18"`, read at **build** time. |
| Binding | `inkwell` 0.11, feature `llvm18-1-no-llvm-linking`, plus `llvm-sys` with `no-llvm-linking` and `disable-alltargets-init`. |
| Linking LLVM | Our own `build.rs`: when the variable is set, it links `libLLVM-18.so` with an rpath and enables the `fa_llvm` cfg. `FA_LLVM_LINK=static` links the needed static components instead. |
| Without LLVM | The crate compiles as an empty shell, and its tests print a skip message: `cargo test --workspace` works on any machine. |

**Why the crate is a normal workspace member.** `default-members` does not help: `cargo test --workspace` builds every member. llvm-sys fails with a `compile_error!` when it cannot find LLVM, so the crate tells it never to link (`no-llvm-linking`, `disable-alltargets-init`, which also stops it from looking for `llvm-config`), and links LLVM itself. Inkwell's per-target initializers (`Target::initialize_x86`...) call exported LLVM symbols, so the C wrappers that `disable-alltargets-init` removes are not needed.

**Dynamic or static.** Measured on this crate (6 cores, `CARGO_BUILD_JOBS=3`):

| | dynamic `libLLVM.so` | static components |
| --- | --- | --- |
| Rebuild after editing one file (tests) | **0.7 s** | 1.5 s |
| Test executable (debug) | **10.8 MB** | 60.4 MB |
| System packages needed | none | the `-dev` symlinks of zlib, zstd, libxml2, tinfo |

Dynamic linking for development, decided. A released `fa` binary is linked statically (one file to ship, only the components it uses), which `FA_LLVM_LINK=static` already supports.

## Runtime strategy

The runtime has two tiers.

**Tier 0, generated by the compiler as LLVM IR** (`src/runtime.rs`): `fa_write`, `fa_exit`, `fa_panic`, `fa_overflow`, `fa_print_i64`, `fa_alloc`, `fa_free`. Each function is emitted on first use, `internal`, into the module that calls it, so it is inlined and dead-stripped with the program, and a program pays only for what it uses. The same IR serves every target, down to a platform layer of three or four calls:

| | `native` | `native` freestanding (Linux x86-64) | `wasm` |
| --- | --- | --- | --- |
| write, exit | libc `write`, `exit` | `write`, `exit_group` system calls | imports `fa.write`, `fa.exit` |
| allocate | libc `malloc` / `free` | bump allocator over `mmap` chunks | bump allocator over `memory.grow` |
| startup | libc's `crt1.o` calls `main` | `_start` in module-level assembly | exported `_start` |
| `memcpy`, `memset` | libc | `rep movsb` / `rep stosb` | `bulk-memory` instructions |

**Tier 1, larger pieces** (Unicode tables, float printing and parsing, hashing, the executor and I/O): written **in Fa on the intrinsics layer** of [Q7](compilation-with-llvm.md#q7-the-internal-intrinsic-layer-for-the-standard-library) wherever possible, so that they go through the same monomorphizer, inliner and dead stripping. What must be C-shaped (system interfaces with structs, `io_uring` setup) is written in C and compiled by **clang 18 to LLVM 18 bitcode**, shipped with the toolchain and linked into the module (`Module::link_in_module`), which keeps whole-program optimization. clang 18 installs without root (`FA_LLVM_WITH_CLANG=1`, 76 MB, checked: it compiles to `wasm32` and native).

Measured on one program, `fibonacci(30)` with `print_i64` and the overflow panic, linked with glibc and lld and stripped (the C and Rust runtimes under the same program written in C):

| Runtime written in | Executable | `.text` | Notes |
| --- | --- | --- | --- |
| LLVM IR from the compiler (the prototype) | **4 832 B** | 502 B | inlined into `main`; no toolchain |
| C, clang 18 `-Oz` | 5 048 B | 477 B | separate object, or LLVM 18 bitcode for LTO |
| Rust `no_std` staticlib `-C opt-level=z` | 9 672 B | 3 834 B | the prebuilt `core` brings panic formatting and needs a `rust_eh_personality` stub; `rustc` uses LLVM 23, whose bitcode LLVM 18 cannot read |

So tier 0 is IR, decided. The wasm and freestanding allocators are bump allocators in the prototype; the real one (size classes with free lists over pages, sized `fa_free`) is written once in Fa on the intrinsics, over a "grow" primitive (`memory.grow`, `mmap`), and serves both.

## Lowering a typed Fa tree

The input is the monomorphic, checked tree of the strategy. Rules for every construct:

- **Functions.** `internal fastcc` (`call fastcc` at each site), `nounwind` everywhere; exported functions and the runtime use the C convention. `noundef` on every parameter and result (definite initialization). Aggregates are passed **by pointer** with `readonly nonnull noundef align dereferenceable(N)` (or without `readonly` for `mutates`); results of up to two scalars are returned in registers, anything larger is written to an `sret` destination provided by the caller. Allocas in the entry block only.
- **Integers.** `Int64` is `i64`, sized integers are `iN`. A sum proven in range is `add nsw`; an unproven one is `llvm.sadd.with.overflow`, then a branch with `!prof` weights (1 : 2^20) to a block that calls the shared cold `noreturn` `fa_overflow` (one compare and one call per check; the prototype verifies that the optimizer keeps both). `//` and `%%` add the floor correction, `Int64.MIN // -1` is checked before `sdiv`, shifts check their amount, and a divisor not proven non-zero produces the typed error. Ranges become `range(i64 a, i64 b+1)` on parameters and results and `!range` on loads.
- **Floats.** `double` and `float`, no fast-math flag ever. `/` is always `fdiv`, with `sitofp` for integer operands. `Integer.round`, `Integer.floor`... compare the value against the integer limits (and NaN) before `fptosi`, which is poison out of range.
- **Objects and tuples.** No named LLVM struct types: an object is a size and an alignment, and a field is a **byte offset** from the canonical layout (`getelementptr inbounds i8, ptr %object, i64 offset`). This is what views need anyway (a view is a set of offsets), it creates no LLVM types to intern, and copies are `memcpy` of a constant size. Only scalars are loaded and stored.
- **Strings.** `{ ptr, length, capacity | flags }`: 24 bytes on 64-bit targets, **12 bytes on wasm32** (pointer-sized words, 11 bytes inline). Literals are private `unnamed_addr` constants with the static flag. `print` of a literal is one `fa_write` of the bytes and the new line, folded at compile time.
- **Arrays.** A `{ ptr, length, capacity }` header inline, elements in a block from `fa_alloc`; an empty array points at a dangling aligned address (a non-null niche). Indexing with an unproven index is `icmp ult` against the length and a cold branch to the typed error; `getelementptr inbounds` only after it.
- **Unions and enumerations.** A tag (the smallest integer holding the member count) and a payload sized and aligned for the largest member, both at byte offsets like fields. `when` is a `switch` on the tag with an `unreachable` default. Enumerations and unions of literals are just the tag.
- **Optionals.** `T?` is a union with `None`. The first version stores an explicit tag; niches (null pointer, spare enum values, ranges) come one by one, behind tests.
- **Errors.** `throws E` makes the result the union `T | E`, returned in two registers when it fits (a tag and one word), in the `sret` destination otherwise. `try` is one compare on the tag with the error path cold, running the scope's cleanups. No `invoke`, no landing pads, no personality.
- **Owning values.** Scope exits emit drops from a cleanup stack; `copy<Shape>` and `drop<Shape>` are generated per shape; trivially copyable values have neither.
- **Module-level values.** Constant data when computable at compile time, otherwise initialized before `main` in dependency order.

## WebAssembly

- **Triple `wasm32-unknown-unknown`**, not WASI. Fa's `wasm` target is aimed at the browser and the edge runtimes (`documentation/guides/web-server.md`), where WASI is absent or partial, and the strategy already gives the runtime its own imports. The module imports a small `fa` namespace (`write`, `exit` today; then clock, randomness and the event loop) and exports `memory` and `_start`. The compiler generates the JavaScript glue next to the `.wasm` (the prototype's is `host/run.mjs`, which runs under Node and Bun). A WASI host is a 20-line adapter of the same imports if a user asks for one.
- **Features**: `+bulk-memory,+mutable-globals,+sign-ext,+nontrapping-fptoint`, supported by every current browser, Node and Bun. `bulk-memory` matters: without it, a variable `memcpy` becomes a call to a `memcpy` the module would have to carry.
- `Integer` stays `i64`; pointers and lengths are `i32`. An `Int64` index is proven in bounds before being truncated.
- A 1 MiB stack (`-z stack-size=1048576`), the memory grows on demand. No threads without the `atomics` feature and shared memory, which is a separate build.
- Traps: a panic calls `fa.exit(101)` after writing its message; `unreachable` only where the compiler proved it.

## Linking

| Target | Command (profile flags in brackets) |
| --- | --- |
| `native` | `cc object.o -o program -fuse-ld=lld -B$LLVM/bin [-Wl,--gc-sections] [size: -s -Wl,-z,noseparate-code -Wl,--build-id=none]` |
| freestanding | `ld.lld object.o -o program -static -z noexecstack [--gc-sections] [size: -s -z norelro -z noseparate-code --build-id=none]` |
| `wasm` | `wasm-ld object.o -o program.wasm -z stack-size=1048576 [--gc-sections --strip-all]` |

The compiler driver knows the C runtime startup objects and the libc, so it stays for `native`, with `lld` behind it (4 520 B for hello world against 6 120 B with GNU ld). Each link is a process that loads the 120 MB `libLLVM.so`, about 30 ms whatever the program size: linking in-process (`lld::elf::link` and `lld::wasm::link` through a small C++ shim) is the first compile-time win to take once programs are real.

Run time of the recursive `fibonacci(40)`, pinned to one core, 15 runs (AMD EPYC):

| Fa `native` `max` | Fa freestanding `max` | Fa `wasm` on Node | `rustc -O -C overflow-checks=on` | `rustc -O` |

The machine code of `fibonacci` is identical in both Fa native builds and as tight as Rust's checked version: the gap between them is code alignment (the function crosses a 64-byte line in one of them). Unchecked Rust is twice as fast because, without the overflow check, LLVM turns one of the two recursive calls into a loop with an accumulator; a checked addition forbids that reassociation. Fa gets the same speed only where the range analysis proves the sum in range.

## Where this plan departs from the strategy

1. **inkwell instead of a wrapper over raw `llvm-sys`** (strategy, "a thin, in-process LLVM"). Inkwell's `'ctx` lifetime was no obstacle for building one module per context, and it covered everything the prototype needed. The strategy's other worries are handled: our own `build.rs` controls linking, and the `Backend` trait of `fa-native` keeps inkwell inside one crate. Attributes inkwell lacks (`range`, `allockind`) are one `llvm-sys` call on the raw handle (`as_value_ref`). Reconsider only if inkwell stops following LLVM releases.
2. **Tier 0 of the runtime is IR, not the Rust `fa-runtime` staticlib** of [Q9](compilation-with-llvm.md#q9-the-native-runtime-and-the-documented-use-of-tokio-and-rayon). The numbers above: a Rust `no_std` staticlib doubled the size of a small program, and cannot be inlined into LLVM 18 code. Q9's executor, I/O and thread pool may stay in Rust, since a program that does not use them does not link them; the allocator, panics, printing and strings may not.
3. **A freestanding Linux target** that the strategy does not have: no libc, static, a hello world of 736 bytes. Proposed as what the `size` profile uses on Linux when the program has no foreign code. It needs the runtime's own allocator, which the `wasm` target needs anyway, and Linux system call numbers per architecture (x86-64 now, AArch64 next).
4. **Objects as byte offsets** rather than LLVM struct types: the strategy only says "a struct stored inline"; offsets fit views and keep the lowering simpler.
5. **Strings are 12 bytes on wasm32**, where the strategy says 24: the layout follows the pointer width.
6. **LLVM 18 is old**: `rustc` already uses LLVM 23, and Ubuntu 24.04 packages up to 20. Pin the newest version that both inkwell (up to 21) and the CI distribution provide when the backend leaves the prototype stage; it is a feature flag and the setup script's package names.

7. **No `Backend` trait nor `fa-native` crate** yet: as `compiler-architecture.md` says, the backend walks the analyzed tree directly (`src/lower/`, through the analyzer's view layer), with inkwell. A recording backend becomes useful with the object cache.

## M1: lowering analyzed files

`fa_codegen_llvm::compile(session, file, path, target, options, output)` lowers an analyzed standalone file (`target`: `Native`, `Wasm`, `NativeFreestanding`; `options`: `opt_level` `O0`–`O3`, `O3` by default, `size` for `default<Oz>` and the smallest link, `emit_ir`), and writes an executable, or a `.wasm` module and its `.mjs` loader (`node program.mjs arguments…`). Until the `fa` command wires it: `cargo run -p fa-codegen-llvm --example build -- file.fa --target=native|wasm [--run -- arguments…]`.

- **Values**: integers in their storage width (`iN`), computed in the compute type of their `ArithInfo` (`i64`, or `i128` signed or unsigned); `Boolean` is `i1`; `Float` and `Percentage` `double`, `Float32` `float`; a string is `{ ptr, usize }` of UTF-8 (no capacity yet, and never freed: drops come with owning values); `T?` of a scalar or a string is `{ i1, T }`; an enumeration member is its index (`i32`), printed `Color.red`; `arguments` is an array `{ ptr, usize }` of strings.
- **Checks, exactly the analyzer's bits** (checked by `tests/checks.rs` on the IR): `OVERFLOW_NATIVE` → `llvm.{s,u}{add,sub,mul}.with.overflow` at the compute width with a cold branch (weights 1 : 2^20) to `fa_overflow`, which prints the exact value (computed in 128 bits on the cold path); otherwise `nsw` (`nuw` for `UInt128`). `SINK_CHECK` → compares against the bounds of `coercions[n]` (ranged types included), then truncates. `DIVISOR_CHECK` → `DivisionByZero`; `MIN_DIV_GUARD` → the `MIN // -1` stop and a `%% -1` that never runs `srem MIN, -1`; `//` and `%%` floor with a select. `CONVERSION_CHECK` → `ArithmeticError` from an integer, a stop from a float (`x > min - 1 and x < max + 1`, NaN fails). A call of a function whose result type is ranged gets `!range`; `nsw`/`nuw` carry the other facts (`mem2reg` drops `!range` on loads of locals, and LLVM 18 has no `range` parameter attribute).
- **Functions**: `internal fastcc nounwind`, `noundef` parameters, arguments in parameter order from `CallInfo`; a parameter with a default value is followed by an `i1` "given" flag and the callee evaluates the default (inlined away at the call sites). Locals are entry-block allocas; a top-level local that a function reads becomes an internal global. Closures over the locals of an enclosing function, function values, variadic parameters are not lowered yet.
- **Control flow**: `if`/`else`, `when` (the analyzer's decision list: literals, alternatives, `none` and the member types of an optional), `while`, `for` over ranges and over the characters of a string, `loop` with `break` values, `continue`, `do`, `return`, `and`/`or`, comparison chains, `??`, `assert`.
- **Runtime**: the platform layer is the IR of `src/runtime.rs`; everything above it is `runtime/fa_runtime.c` compiled to IR (see decisions.md, "Tier 1 runtime in C"): a text builder for `console.log`, interpolation and `toString` (values brief D-5, D-6, as the JavaScript runtime), strings in grapheme clusters (an approximation of UAX #29: combining marks, Hangul, emoji sequences, flags), stops (`stop: <reason>` and `  at file:line:column`, exit 101), escaped errors (exit 1), and the 128-bit `__multi3`/`__divti3` family for wasm32 and freestanding. A `console.log` of literals is one constant write.
- **Tests**: `tests/programs/*.fa` and every analyzer case that prints something and expects no diagnostic, compiled, run and compared on `native`, `native-freestanding` (x86-64 Linux) and `wasm` (Node or Bun), with the `-- prints:`/`-- exit:` annotations.

Measured (`cargo run -p fa-codegen-llvm --release --example report`, AMD EPYC, shared machine):

| | Fa native `O3` | Fa freestanding | Fa wasm (Node) | `rustc -C opt-level=3`, overflow checks | `rustc -C opt-level=3` |
| --- | ---: | ---: | ---: | ---: | ---: |
| `fib(42)`, recursive | 1 472 ms | 1 409 ms | 2 535 ms | 1 488 ms | 908 ms |
| Collatz below 3·10^6 | 707 ms | 773 ms | 2 511 ms | 781 ms | 476 ms |
| `fib` executable, stripped | 7 864 B | 6 152 B (3 128 B `size`) | 3 760 B (2 076 B `size`) | 339 176 B | |

## M1b: errors, objects, collections

What the analyzer handled next, lowered the same way (design/decisions.md, "Errors", "Value layouts"):

- `try`, `throw`, `catch` (errors as result returns), `Integer.parse`, `Integer.round` and friends; `DivisionByZero`, `ArithmeticError`, `IndexError`, `ParseError` are catchable.
- Objects (typed and anonymous literals in written order, defaults, spreads, fields, `.=`, structural conversions and equality, methods with `self`), named unions and `Errors` with data, enumerations, anonymous unions (boxes with the id of the member type), `is`, `when` with ranges, alternatives, member types and `as` bindings, optional chains `?.`.
- Arrays (literals, `Array.from`, indexing with `INDEX_CHECK`, slices, the Array API with callbacks: `map`, `filter`, `reduce`, `sort` (stable merge sort with a C-convention comparator trampoline)…), tuples, ranges as values, destructuring from the analyzer's `PatternInfo`, variadic parameters, lambdas and function values with captures, generics by monomorphization.
- The number API (`Math.max`, bitwise methods, shifts with `SHIFT_CHECK`, `wrapping*`, `saturating*`, `checked*`, float methods).
- `--overflow-checks=false` (`Options::overflow_checks`): `OVERFLOW_NATIVE` and `SINK_CHECK` are ignored, integers wrap (plain `add`, never `nsw`), `MIN // -1` divides by 1; the other checks stay. `fa build` wraps by default, `fa run` checks.

Measured with `bun benchmarks/run.ts fib sieve mandelbrot fannkuch-redux` (shared machine; the other six benchmarks need `mutates`, `use`, `Map` or recursive types from the analyzer):

| | Rust `-O3` | Rust overflow checks | Fa native (wraps) | Fa native, checked | Fa wasm (Node) | Fa native size | Rust size (stripped, `panic=abort`) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| fib(42) | 930 ms | 1.67 s | 812 ms | 1.52 s | 2.09 s | 11.4 KiB | 331 KiB |
| sieve(10^8) | 995 ms | 907 ms | 1.04 s | 1.12 s | 1.40 s | 12.0 KiB | 332 KiB |
| mandelbrot(4000) | 1.17 s | 1.18 s | 1.13 s | 1.19 s | 1.15 s | 13.0 KiB | 331 KiB |
| fannkuch-redux(10) | 259 ms | 246 ms | 666 ms | 645 ms | 816 ms | 13.2 KiB | 332 KiB |

The fannkuch gap was the copy of `current = permutation` at every permutation (an allocation, never freed): an array assigned to an array local now reuses the local's block (about 350 ms after the change). The wasm gap on `fib` (1.3× in CPU time, measured idle; 1.17× with `node --no-liftoff`) is the overflow check, which wasm can't read from a flag (four more instructions per checked add), and V8's stack check per call; the proof of concept's parity was a lucky run.

## M2: memory, references, recursive types, maps and sets

What `design/decisions.md` records under "Memory management", "Allocator", "Parameters a function changes" and "Maps and sets", in `src/lower/ownership.rs`, `references.rs` and `tables.rs`, and the allocator and tables of `runtime/fa_runtime.c`.

- **Ownership**: `take` (a temporary or a last read moves, a place read copies) at every owning position, `fresh` for every value a statement computes, a cleanup stack of owned locals and temporaries; code evaluated conditionally is a region of its own, so that a drop is dominated by what it drops (the verifier catches a missing region).
- **Tests**: every program of `tests/programs`, of the `fa` command and of the analyzer's cases runs with `Options::leak_check` on the three targets; `tests/memory.rs` runs two loops allocating about a gigabyte each in 128 MiB (`ulimit -v`, the loader's `FA_MEMORY_LIMIT` on wasm), and a program keeping its strings fails there with `out of memory` / exit 103.
- **TBAA**: array headers and program values have distinct type tags, so a store into an item doesn't reload the length or the items pointer.

## M3: relations, columns, reactivity (fourth shift)

What `design/decisions.md` records under "Relations", "Columnars by columns", "Compile-time values", "Reactivity" (natively) and "Disjoint references":

- **Relations** (`src/lower/relations.rs`): sides as element addresses or runtime sets of addresses (`FaLinks`), two-sided writes and unlinks in the runtime at byte offsets, copies without links, owner copies relinked through an address map. The four relation cases of the analyzer run on every target, with `tests/programs/relations.fa`.
- **Columnars by columns** (`src/lower/columns.rs`): one run per field per chunk, references are slot addresses, `Repr::Row` places gather and scatter; `for` over pools and columnars walks chunks and occupancy words in generated code.
- **Compile-time maps, sets, members and ranges** (`src/lower/constants.rs`).
- **Reactivity** (`src/lower/reactivity.rs`): sources, derived and watch observers in the runtime, flush after the statements of `flush_after`, the 100-round stop; `reactivity.fa` and `reactivity-rounds.fa` of the `fa` command run natively.
- **Disjoint references** (`src/lower/aliasing.rs`): scoped alias metadata for `body`/`other` in nbody's loops.

## Performance of the Goose suite (fifth shift)

What `design/decisions.md` records under "Simple strings" and the entries after it: an ASCII flag in the capacity word of strings (constant-time positions, static one-byte characters, no allocation for `letters[i]`), native string slicing, loop bounds checks shaped for `irce` (run after `default<O3>` with `licm`, `reassociate` and a second vectorization), scalar TBAA, 16-bit arithmetic for byte sums, early boxes for recursive fields, moving `filter` of a temporary array, template appends, code points read without their array, and a wasm loader with only the imports used. Profiled with callgrind (instruction counts are stable on the shared machine) and CPU-time medians; `tests/checks.rs` checks the vectorized byte kernel, the 16-bit arithmetic, the string flags and the early boxes.

## Byte access (sixth shift)

`text.bytes()` (`design/decisions.md`, "Strings: byte access") read in place natively, and the Goose ports reading bytes where Goose does: `calc` and `sexp` parse `self.text.bytes()` instead of an `Array(Character)` (24 bytes per character). The shift also built inline strings, nullable `Node?` edges, statement regions and early boxes for pushed recursive items, which the merged `perf/native-goose` work replaced (its inline strings, nullable edges, root arenas and inline recursive collection items): measured on top of it, statement regions gained nothing on `binary-trees` and `calc` (their trees are already in its arenas, without a drop walk), and `scene` already runs at Goose's speed. They are kept on the branch `sixth-wip` of the shift's worktree, not merged.

## Native representations of the Goose work (`perf/native-goose`)

Six commits merged into `compiler` on 2026-11-04, reviewed and cleaned the same day. Every rule is chosen from the types, the proven uses and the target, never from a benchmark's name, size or output; no check is removed without a proof; the benchmark sources are unchanged. `design/decisions.md` ("Native representations") records the choices; the audit tools are in `benchmarks/audit/`.

| Area | What the backend does | Condition |
| --- | --- | --- |
| Module constants | A module `let` of a literal or compile-time value is an LLVM `constant` global, folded into loops. | No initializer evaluated at run time. |
| Literal array lengths | `xs.length` of a literal array reached through `let`/`static` bindings is a constant; the array is still evaluated (`constant_array_length`). | No spread, no `mutable`, `use` or destructuring on the way. |
| Borrowed parameters | Direct synchronous calls pass objects, strings and tuples by address (LLVM infers `nocapture readonly`); a structural view of another layout is adapted; a narrowed optional is unwrapped (`argument_place`). | Indirect calls, coroutines and defaults keep their convention; `static` values and members without data go through a temporary. |
| Nullable pointers | `T?` of a recursive edge, a boxed union or an array (a pointer to its header, even empty) is a nullable pointer (a `binary-trees` node is 16 bytes, not 32). | A present box or header is never null. |
| Inline small unions | A non-generic named union whose payloads (scalars up to 64 bits, strings, objects without destructor) fit 3 machine words is `{ tag, payload }` without a box (`inline_unions.rs`); padding is zeroed at construction and frozen before word-wise use. | The choice depends on the type only, so every file of a program agrees. Inlining 40-byte payloads made `Array(Event)` wider and `records` slower (0.43 → 0.61 s): larger unions stay boxed until collections store variable-size payloads. |
| Root arenas | Nodes of a recursive object or union built by its builders are bumped in 64 KiB page-aligned chunks owned by the root; dropping the root frees the chunks without walking the edges; a copy gets its own region; owning string and array payloads register a cleanup (`trees.rs`, `fa_arena_*` in the runtime). | A closed proof: one file, no generics, async or foreign calls; edges only to the same root type; nodes no bigger than a page; roots never kept by another object, collection, tuple, union payload, capture or global; nodes never written outside the builders' own mutable locals; every constructor in a builder's own body. Members without data are constant boxes outside the regions. |
| Recursive collection items | An `Array`, `Map`, `Set`, growing collection, pool or columnar of a recursive object stores the object in its slot, without a second box; callbacks borrow the slot. | A finite layout across the type graph; direct cycles keep their box. |
| Allocation | The allocator's fast path includes the page bump; `fa_alloc` returns `noalias nonnull`; 64-bit native targets reuse 2 MiB spans, aligned and advised `MADV_HUGEPAGE` on Linux (ordinary alignment when refused). | Some small programs have a larger RSS. |
| Inlining | Small leaf functions; the runtime's merge sort (element size and comparator known); the scalar base case of a direct recursive call evaluated at the call site (`inlining.rs`); the runtime IR loses `optsize`/`minsize` for speed builds. | The base case: pure scalar parameters, `if c { leaf } else { … }` with at most 16 nodes, no ranged result. |
| Loops and arithmetic | A 64-bit division by an immutable binding declared outside the loop uses a reciprocal and one exact correction (`division.rs`, native only); array iteration loads the pointer and length once; a counted loop reserves its pushes to an initially empty array field; a directly returned passive local is moved; Float to Integer has one ordered hot guard. | Zero, the signed minimum and floor division keep their paths; field pushes keep their capacity checks (aliases may push more). |
| Text and tables | Inline strings (23 bytes, 11 on wasm32), two digits at a time in decimal conversion; `Map` entries in stable 32-slot chunks, a 32-bit index with a 64-bit fallback, probes reused within one insertion or deletion, no key comparison after a full-hash match for integers up to 64 bits (an injective hash). | Owned by the strings and maps work; documented in the implementation sections of the strings and maps pages. |

**Review** (2026-11-04): adversarial programs (`arena-*.fa`, `inline-union-kinds.fa`, `borrowed-narrowed-optionals.fa`, `optional-arrays.fa`, `inline-unions-across-files.fa`) run on the three targets with leak checks: fields, subtrees and destructured parts of temporary roots, builders taking roots, regions on worker threads, children of union roots, roots in general unions, every member kind of an inline union. No unsoundness was found in the arenas, inline unions or array lengths; the borrowed parameters failed to compile a narrowed optional (now unwrapped) and widened a value into an optional parameter as if narrowing it (garbage), and a `none` type id crashed the box helpers. Generalized since: members without data in arena unions, inline unions across files, `Array?` nullable. Cleaned: the proof split into its steps, one target-data helper, the inline layout computed once per union, the loop bodies of invariant divisors computed once per file.

**Measured** (CPU-time medians against Goose `-O2` with clang 18, from the fifth shift to the merge): `scene` 5.5x Goose to parity (children inline in their arrays, exact reservations, huge pages: 5.6x faster), `binary-trees` 3.8x to 1.2x (arenas and nullable edges: half the instructions), `interp` 2.7x to 0.7x, `fib` to 0.9x (the base case at the call site); `string-building`, `sort-objects`, `respond` and `calc` execute 22 to 44 % fewer instructions. Peak RSS fell by 68 % on `lru` and 36 % on `word-count` (stable `Map` chunks), 25 % on `tree` and 15 % on `interp` (8-byte arena granularity). Identical binaries varied by up to 10 % between series on the shared machine, so smaller differences are noise. The current ratios are in `benchmarks/README.md` ("Against Goose on its own suite").

**Remaining gaps**, each with the proof it needs:

- Unions larger than 3 words stay boxed (`records`): variable-size payloads in a collection buffer with an offset index, promoted before overflow.
- Arenas stop at collections of roots (`Array(Sexp)` in `sexp`): one owner per region, children freed once, subtree copies and extractions covered.
- Small arrays inline in nodes need a proven length bound on every construction and write path (a field name or an observed size is not a proof).
- Tables: hash fingerprints or control groups before reading entries; a probe reused by `includes`/`get` then `[]`/`delete` (tied to the table's version and the key, invalidated by any mutation or unknown call); smaller hash and presence words; presized tables from loop cardinalities; small maps stored in their header.
- 32-bit links or node numbers (Goose's relative links), with a promotion before overflow, never a hidden 4 GiB limit.
- Key and substring views without copies (`words`), alive and unchanged for the whole borrow.
- Index facts: `lru`'s `Integer` links keep their `IndexError` checks until a relational proof reaches the backend; invariant divisors shared across functions; fused `split`/`filter`/`count` scans and templates; values built in their destination.
- Measuring: 15 Goose ports get `N` as a compile-time constant while Fa reads it; `benchmarks/audit/compare.py --goose-runtime-size` gives Goose a run-time `N` (its `blur` then fails its `checkfree` proof, which is reported, not bypassed).

## Generic function values (phase 2 of "Generic functions carry their list on the function value")

A value of a generic function type, `<T>(value: T) => T`, is passed with the instances its receivers need, without boxing (`lower/generic_values.rs`):

- **Representation**: the pair every function value is, `{ ptr table, ptr environment }`. `table` points to a constant array of entries, one per instance, each with the indirect call convention of its instance (`indirect_type`); the environment is the lambda's, shared by its instances (built once, with the copy and drop of any closure environment). A call `transform(1)` loads `table[i]` and calls it with the environment; a conversion to a function type that isn't generic (`[1, 2].map(<T>(value: T) => value)`, `apply(same)`) is the pair `{ table[i], environment }`, a view of the value.
- **Instance sets**: per *class* of generic function types, the types equal once their parameters are renamed in order and their constraints erased (`<T>(value: T) => T` written by a type alias, a parameter or a lambda is one class). Every call of a value of the class and every conversion to an instance adds its type arguments, under the bindings of the instance being lowered (`transform(value)` in `both<U>` adds `U`'s type for each instance of `both`). The index of an instance in its class is fixed when it is first met, so code lowered earlier keeps its indices.
- **Producers and their tables**: a generic lambda under the bindings of the instance around it, or a generic `function` declaration given as a generic value. Each has its own table, filled at the end of the lowering with an entry per instance of its class (`lambda_instance`, or the declaration's instance and thunk), until no entry asks for another instance (an entry's body may call generic values). A producer is only reachable from places of its class whose constraints its own constraints accept (the analyzer's rule: an implementation's constraint is never narrower than its type's), so an instance its constraints exclude is never called: its entry is a trap (`fa.generic_instance_never_called`).
- **Fields, collections, returns**: the representation is the same everywhere; a place's readers are the calls and conversions of its class, which every producer's table already serves. Granularity: the class is the union of the needs of every receiver of the type (sound, simple, few instances in practice); a set per receiver (a parameter of a given instance, a field) is a refinement that needs the flow of values between places, not done.
- **Recursion limit**: a class with more than 64 instances is a polymorphic recursion (an instance calling the value at a new type, `again([value], …)` from the instance at `T`): an error at the call that keeps asking, with the first types (`Array<Integer>`, `Array<Array<Integer>>`, …).
- **Units**: the tables are a property of the whole program; a program compiled per unit with a generic function value is compiled as one module (`Unsupported` from the unit, the existing fallback).
- **Also**: lambdas inside generic functions are declared per instance of the function around them (keyed by the representations of every bound parameter; they weren't compiled natively before), a generic declaration given where an instance is expected (`names.map(identity)`) is its instance's thunk, and `first<Integer>(items)` reads the type arguments written before the call.

JavaScript erases all of it: a generic function value is a plain function.
