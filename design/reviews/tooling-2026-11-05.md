# Tooling review, 2026-11-05

Scope: `packages/cli` (`fa`, `fa-native`), `packages/formatter`, `packages/language-server`, `packages/codebase-parser`, at `compiler` 7a75f47.
Release build, `ulimit -v 8000000`. The scripts that reproduce the findings were run from a scratch folder (`$S`). Ranked: bug > missing test > cleanliness.

## Bugs

1. **Critical. A lockfile can delete any folder** (`dependencies.rs:486` `source_folder`, `:1511`, `:1600`). The `hash` of an entry is joined to the cache path without validation, and a cache entry whose content doesn't match is `remove_dir_all`ed. Evidence: a lockfile entry `hash = "sha256:$S/poc/victim"` for a declared `file://` source, then `fa check` gives `DEP001`, and `$S/poc/victim` is gone (`find: No such file or directory`). An absolute path replaces the cache root, and `../` escapes it. The LSP reaches the same code by opening a file (`project.rs:300` `editor_session` → `resolve`). Fix: `read_lockfile` accepts only `sha256:` followed by 64 lowercase hex characters, and the cache removes only folders under `cache_root()`.
2. **High. Git argument injection** (`dependencies.rs:572`). The URL is passed to `git clone` with no `--` before it. With `"git+--upload-pack=touch…@1"`, git parses it as an option (`fatal: repository '…/.partial-…git' does not exist`, so the URL was consumed as an option). It is blocked here only because a single positional argument remains. Fix: pass `--` before the URL, and reject URLs that start with `-`.
3. **High. Any dependency can read local files** through `file://` sources (`dependencies.rs:279`, `:668`). A Git library's own `dependencies.fa` can declare `"file:///home/u/.ssh/id_rsa"`, which is fetched, cached, and handed to `generate` (whose output is compiled into the program). The docs list only `https` sources. Fix: accept `file://` only in the root package, or only behind a test variable (`FA_ALLOW_FILE_SOURCES`).
4. **High. `fa develop` loses edits made during a reload** (`develop.rs:850`, `:878`, `:956`). After `Loaded::load`, `Watcher::new` takes a new snapshot, which absorbs the files changed while the package was loading. Evidence (`devrace.sh`, the 1,000-file package): add `library/zz.fa`, then edit `application/main.fa` 2 s later. The output shows `zz.fa was added: running again`, and the edit never runs (`SECOND-EDIT printed: 0` after 40 s). The same happens in `fa test --watch`. Fix: take the snapshot before loading, or keep the old snapshot and compare it after the load.
5. **High. Concurrent `fa run` of one package fails** (`run.rs:257-260`, `streaming.rs:571-581`). The command does `remove_dir_all(program)` and then a `rename` into the shared cache folder. Six parallel runs give one `fa build: can't write into …/program: Directory not empty (os error 39)`, exit 1. Fix: run from a folder per process (or a lock file), and swap the folder with a rename only.
6. **Medium. `x.fa.fa` is unreadable**: `trim_end_matches(".fa")` strips the suffix repeatedly (`project.rs:76`, `:91`, `:208`, `:296`, `develop.rs:216`, `:257`, `dependencies.rs:2176`). `fa check one/x.fa.fa` prints ``fa: can't read `…/one/x.fa` `` and exits 1. Fix: use `strip_suffix(".fa")`.
7. **Medium. `fa format` follows symbolic links**, including links that form a loop (`format.rs:55`, `:156`, which use `path.is_dir()`). A `library/up -> ..` link yields 82 files for one real file (paths `library/up/library/up/…` 40 levels deep, until `ELOOP`), and without `--check` the same file is rewritten 41 times. Fix: use `entry.file_type()` like `collect_fa_files`, and skip links.
8. **Medium. Every workspace command resolves the whole workspace once per package** (`project.rs:389` → `scope_of` → `resolve`, which reads every `.fa` file of every package in `package_imports`, `dependencies.rs:998`, and re-hashes every cached dependency in `materialize`). Evidence (`wsreads.sh`, strace): `fa check` of 8 packages × 50 files opens `p1/library/f1.fa` 9 times and `p8/package.fa` 18 times. The cost is O(packages²), and it is paid again for each extra target in `check_one`. Fix: resolve once per command and share the `Resolution`.
9. **Medium. A standalone file scans its whole folder tree** (`codebase.rs:523`, up to 5,000 files). In a folder with sub-projects, `fa check --timings hello.fa` spends 176.6 ms in `scan` and 8 ms in analysis. In `~` it walks the home folder. Fix: scan lazily, only the names the file looks up, or limit the depth.
10. **Medium. The language server never sees changes on disk** (`server.rs` has no `didChangeWatchedFiles` handler, and the capabilities don't register a watcher). After a `git pull`, or a file added or deleted outside the editor, the diagnostics stay stale until a restart. Fix: register file watchers for `**/*.fa` and `dependencies.lock`.
11. **Medium. The language server runs network I/O on the analysis thread**: on first open, `editor_session` runs `git clone` and `curl --max-time 60`, so all queries freeze meanwhile. Fix: resolve the dependencies on a background thread, and analyze without the dependencies until they are resolved.
12. **Medium. Manifest paths are checked only for `/` and `..`** (`dependencies.rs:1623`). `..\x`, `C:\x` and `\\host\x` pass, and on Windows `partial.join(path)` in `store` (`:508`) escapes the cache folder. Git tree paths from `ls-tree` (`:617`) are not checked at all. Fix: allow only `[A-Za-z0-9_./-]` segments, none empty, `.` or `..`, on all systems.
13. **Medium. `fa check` errors for other targets are dropped** (`lib.rs:504`, `let Ok(other) = Loaded::load(path, target) else { continue }`). A dependency that fails `DEP009` for `native` disappears from the report. Fix: report the error with its target.
14. **Low. No error total**: the text report prints `1 error` after each file (`report.rs:145`). With 200 errors, the output ends with 200 `1 error` lines and no grand total. Fix: print the per-file counts only once, then `N errors in M files` at the end.
15. **Low. `fa run` failures say `fa build:`** (`streaming.rs:364`, `:382`, `:434`; see item 5). Fix: pass the command name to `streaming::build`.
16. **Low. `focus_forbidden` takes the last segment of the branch name** (`project.rs:663`, `rsplit('/')`): `origin/release/1.0` becomes `1.0`, which never equals `release/1.0`, so `TEST004` is not reported on that default branch. Fix: use `strip_prefix("origin/")`.
17. **Low. `is_versioned` is a substring heuristic** (`dependencies.rs:315`): `https://dev1.example.com/x.fa` counts as versioned (`v1`), and so does any IP address. Fix: look for a version only in the path segments (`@x.y`, `/vN/`).
18. **Low. `http://` sources are accepted silently.** The first fetch is not protected, because the lock records whatever arrives. Fix: warn on `http://`, as `DEP004` does.
19. **Low. The hot-reload channel accepts the first local connection** (`hot.rs:284`, no token): any local user can take it before Bun connects, and then every swap fails. Fix: pass a random token in `FA_HOT_CHANNEL`, and check it on connect.
20. **Low. A test file that hangs blocks `fa test` forever** (`testing.rs:282`, `output()` with no timeout). Fix: add a per-file timeout (`FA_TEST_TIMEOUT`), then kill the file's process and report it.
21. **Low. `apply_edits` silently skips a file it can't read** (`develop.rs:217`), such as a non-UTF-8 file or one deleted in between. The edit is then ignored with no message. Fix: print the read error.
22. **Low. Unhelpful message for a non-UTF-8 file**: `fa format bad.fa` prints `bad.fa: stream did not contain valid UTF-8`, and `fa check bad.fa` prints ``fa: can't read `…/bad.fa` `` (no reason). Fix: say "is not UTF-8 text: save it as UTF-8".

## Missing tests

23. No test for the codes `DEP003` (tag ≠ `package.fa` version), `DEP006` (unreachable repository), `DEP009` (target not supported) or `DEP007` "outside the folder" (grep of `packages/cli/tests`: none). Only `DEP001`, `DEP002`, `DEP005`, `DEP007` (missing manifest), `DEP008` and `DEP010` are tested.
24. No test for a malformed lockfile: invalid syntax (the `not a valid lockfile` path), a forged `hash` (item 1), or a damaged cache entry being refetched (`dependencies.rs:1507-1512`, `:1600`).
25. `develop.rs`, `project.rs` and `workspace.rs` have 0 unit tests. `Watcher::poll`/`merge` (the vim save pattern: removed then added), `reload_reason`, `focus_forbidden` (item 16), `locate` for scripts and `shown_base` are covered only end to end, or not at all.
26. `TEST004` (`test only` on CI or the default branch) has no test under `packages/cli/tests` (grep: only `src/`).
27. `develop.hotReload = false`, `develop.open`/`FA_OPEN_COMMAND`, and a hot-swap failure that falls back to a restart (`Reload::Restart` from `swap`) have no test.
28. No test for concurrent commands (item 5), symbolic links (items 7 and 12), or edits during a reload (item 4).
29. `migrate.rs` (675 lines, hidden command) has 3 unit tests; `bind.rs` (2,513 lines) is tested only through `tests/foreign.rs`.

## Cleanliness

30. Doc comments attached to the wrong item: `lib.rs:190` ("Whether the analysis found errors." sits above `c_libraries`), and `testing.rs:92-97` (the doc of `configures_asynchronous` sits above `configured_asynchronous`, which leaves the former undocumented). The two functions should also be merged into one.
31. `resolve` defines the same `major` closure twice (`dependencies.rs:1125`, `:1144`), and builds the change list with two O(n²) loops. Fix: use one helper, or a map keyed by (source, major).
32. `dependencies.rs` has 2,379 lines covering versions, the lockfile, the cache, git, remote sources, resolution and mounts. Split it into modules. `fetch_remote` (about 150 lines), `develop()` (about 180 lines) and `Developed::start` (about 110 lines) are too long.
33. `Discovered::closest` has a dead arm (`workspace.rs:96`): `discover` stops at the workspace, so the package found is always inside it.
34. The module path is computed from a file path in 6 places (`replace('\\', "/")` + `trim_end_matches(".fa")`; see item 6). One helper would fix item 6 everywhere at once.
35. `Resolver::resolve_git` rebuilds every group on each of up to 32 iterations, calling `choose` → `materialize` (which reads and hashes the tree) for every unchanged group, and `latest_major` pushes a `DEP004` warning on each iteration. Fix: cache `Chosen` by (repository, version).
36. Small quadratic lookups: `mount` uses `reached.contains` (`:2158`), and `Report::file`/`merge_target` scan linearly. They are harmless at today's sizes; a `HashSet` or `BTreeMap` would remove them.

## Measurements (good news)

- `fa version` and `fa help`: 0.00 s, 3 MB RSS. `fa` links no LLVM (5 shared libraries, `fa-native` 18 MB).
- `fa check` of the generated 1,000 files (3.4 MB): 4.7 s and 99 MB on the pipeline. With `FA_PIPELINE=0`: 11.6 s and 331 MB. With 200 errors: 4.8 s and 100 MB.
- `fa format` of the same 1,000 files: 1.3–2.2 s (about 2 MB/s on one thread) and 4.6 MB peak. Formatting files in parallel would be an easy 4× gain.
- Language server on the same package: first diagnostics after 2.4 s, then 97 → 100 MB over 200 edits (stable).
- A cycle between workspace packages is reported as `MOD007`, with no hang.
