## Performance (Goose suite, native, vs Rust)

- **User decisions of 2026-11-03** (see `design/decisions.md` "Minimal representations"): characters as views over UTF-8 bytes (sexp's text is bytes, not `Array(Character)`), strings < 64 bytes never on the heap (inline ≤ 23 bytes, stack buffers ≤ 64 bytes when not escaping), `capacity`/`reserve` on strings and every collection (no-op on JavaScript), parameters never copied (always by reference), module `let` constants folded, small hot-path helpers inlined. To implement on resume: analyzer (builtins `capacity`, `reserve`, `from(capacity)` everywhere; escape facts for stack strings), native (layouts), JavaScript (no-op `reserve`), documentation (strings, collections, functions pages).

- **Goal (user, 2026-11-02): Fa faster than Goose on Goose's own benchmarks, in sync mode, release builds**, using the strict typing of the checker for optimizations (ranges, index proofs, alias rule → `noalias`, immutability, narrowed types → unboxed layouts, purity → `readnone`, non-escaping → stack allocation). *LLVM fifth shift: Fa/Goose 3.96 → 1.9 on the Goose suite (CPU time 1.94; ahead or level on `sum`, `push`, `tree`, `graph`, `particles`, `blur`); see "Against Goose on its own suite" in `benchmarks/README.md`.* Left, structural, by expected gain: inline strings (≤ 23 bytes) and `Character` as a scalar (`calc`, `sexp`, `strlist`, `words`, `records`, `respond`); `T?` of a reference as a nullable pointer (`tree`, `binary-trees`: nodes from 40 to 24 bytes); pools for the boxes of a recursive value freed at once (`binary-trees`, `interp`, `calc`); field layouts narrowed by ranges the analyzer proves for every store (`lru`: `Integer` fields that hold indices); map entries without a stored hash and 32-bit index slots (`lru`, `words`); `scene` (Transform copies by value).
- **Open from the review of the Goose work**: arenas and the closed tree proof are single-file (a whole-program proof is needed); `benchmarks/audit/compare.py` and the first audit's shell scripts overlap (one driver would do).
- **Split aggregates without fragments (native, proposed by the native-goose work, not implemented)**: a `let parts = text.split(sep)` read only through `parts.length` and `parts.join(literal).length` (string-building), or the chained `text.split(sep).length`, needn't build the array. Sound plan: the uses are syntactic (no other read, no capture, no alias, no `use`), the text and separator are evaluated once at the declaration; at run time, when the text and the separator are simple (ASCII, no `\r`) and the separator isn't empty, store the count of non-overlapping byte matches + 1 and the byte length of the text instead of the array (graphemes are bytes there, and a simple `literal` can't form a cluster across a boundary); otherwise build the array as today (a null-or-array slot, dropped when built). `.length` is then the count, `.join(literal).length` is `bytes - (count - 1) * sep.length + (count - 1) * literal.length`. Tests: mutated sources and separators after the declaration, empty texts and separators, non-simple texts and literals, evaluation order, leak checks. `string-building` is already 0.88x Goose (2026-11-04), so the gain is small. Since the split views (`src/lower/views.rs`), a split into views costs one count of the separator byte and three stores per part: still not done, the gain is smaller still.
- **`lru`'s narrow fields and index proofs (native gaps work, 2026-11-04)**: not provable with today's facts. The analyzer's ranges are intervals of expressions and of declared types; it has no per-field fact over every store (`analysis.rs`), and `Node.previous`/`next` receive parameters (`index`), map values and other fields, all `Integer`. A sound 32-bit `previous`/`next` (and `unlink` without its four checks) needs a relational invariant: every value stored into those fields, into `free` and into the values of `positions` is an index of `nodes`, and `nodes` never shrinks (Goose's typed pool references; in Fa, an index type tied to an array, or a whole-program value-flow analysis with array-length bounds checked at growth). `key` and `value` can't narrow at all: `key` comes from the run-time size, `value` grows by `+= 1`. So proofs give at most 24-byte nodes; 16 bytes needs the program to say `Int32`. `unlink` is now inlined (leaves of up to 64 nodes, `src/lower/mod.rs`).
- Bun: `push` exceeds a 4 GB cap through the generator's dead bigints, and the 64-bit generator compiled to `BigInt` dominates the Goose-suite times on Bun (inline shifts helped; see `design/decisions.md`). Next step: 64-bit values as two 32-bit numbers in JavaScript, at least in functions that only use bitwise operations.

- **Index proofs across units**: the never-negative fact is published per unit; the index proofs themselves still need a single-file program (which array a claim refers to across units). Design in `design/decisions.md`. After the Goose gaps.
